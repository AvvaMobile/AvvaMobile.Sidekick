# Sidekick Security

Status: Mandatory requirements. To report a vulnerability, see [.github/SECURITY.md](../.github/SECURITY.md).

Sidekick combines remote web content with local source-code execution. Security boundaries are therefore architectural requirements, not optional hardening.

## 1. Trust model

Trusted:

- packaged Sidekick application code
- validated local user actions
- selected local project path

Untrusted or partially trusted:

- all remote web content
- DOM data from ChatGPT
- text generated by ChatGPT
- text generated by Claude
- repository contents
- terminal output
- URLs opened from remote content

Generated text is data. It does not become privileged merely because an AI produced it.

## 2. Electron remote-content requirements

For ChatGPT WebContentsView:

- nodeIntegration = false
- contextIsolation = true
- sandbox = true where supported
- webSecurity = true
- allowRunningInsecureContent = false
- no experimental features
- no generic preload API
- no remote module
- no direct IPC exposure
- navigation allowlist
- window-open allowlist
- permission request handler

Follow current Electron guidance:
https://www.electronjs.org/docs/latest/tutorial/security

## 3. Microphone permission

Microphone access is used only for ChatGPT's own voice mode.

Permission is granted only when:

- the requesting origin and the top-level page are approved ChatGPT origins
- the request comes from the main frame (subframes are denied)
- only audio is requested (camera and screen capture are denied)

Sidekick never asks for the microphone on its own at startup. On macOS the system prompt is triggered once, from the setup popup's Allow button (D037); on Windows the OS microphone privacy setting applies.

All unrelated permission requests are denied by default unless explicitly required and reviewed.

## 4. Navigation

The ChatGPT view may navigate only through a maintained allowlist needed for ChatGPT and legitimate authentication flows.

Unknown external destinations must not silently replace the ChatGPT surface.

External links should be handled through a safe explicit flow.

Never pass an untrusted URL directly to shell.openExternal without validation.

## 5. Local privilege isolation

Remote ChatGPT web content must not be able to:

- read arbitrary files
- write files
- spawn processes
- execute shell commands
- call Git
- access Claude session data
- call Sidekick IPC
- obtain environment variables

Only the local trusted shell can request privileged operations, and only through narrow typed IPC.

## 6. IPC

Every IPC handler must:

- use an allowlisted channel
- validate input schema
- validate sender
- return typed errors
- avoid shell interpolation
- avoid accepting arbitrary executable names or command strings

No generic runCommand IPC exists.

## 7. Claude execution

Claude runs as the user's own interactive Claude Code in the Workspace terminal (D033):

- in the exact project folder of that Workspace
- with a validated executable resolution
- with the user's own Claude settings and permission rules; Sidekick's `--settings` file only adds its hooks
- never with `--dangerously-skip-permissions` or any other permission-skipping flag

A prompt is pasted into Claude only when the user clicks Send to Claude (or ⌘⇧↵), or when the user's own latest ChatGPT message explicitly asks for it (D034, cancellable countdown). ChatGPT output alone never starts a task. The prompt is cleaned of control and escape characters before it is pasted.

Any future change to Claude permission automation requires a documented security decision.

## 8. Prompt transport

Only the explicit approved prompt is sent to Claude.

Do not attach:

- ChatGPT cookies
- browser local storage
- unrelated conversation history
- passwords
- environment files
- tokens

## 9. Result transport back to ChatGPT

Before creating the review packet, redact or omit obvious secrets where feasible.

At minimum:

- never automatically include .env file contents
- never include keychain data
- avoid dumping complete environment variables
- do not include binary content
- cap terminal/log sizes

Sidekick prefers Git filenames and diff statistics over unrestricted repository dumps.

## 10. Authentication storage

ChatGPT authentication remains inside Electron/Chromium persistent session storage.

Sidekick does not implement a custom password store for ChatGPT.

Claude Code authentication is owned by the installed Claude Code CLI.

Sidekick does not copy Claude credentials into its own state.

## 11. Project path validation

Before spawning a managed task:

- path exists
- path is a directory
- the Workspace record owns the path
- canonical path is resolved
- no task-supplied path override is accepted from ChatGPT content

## 12. Shell safety

Do not construct commands through unescaped shell strings when a direct process spawn API can be used.

Pass executable arguments as an argument array.

Prompts are never passed on a command line. They reach the terminal Claude as one bracketed paste after all control and escape characters (including any embedded paste-end sequence) are removed, so prompt text cannot inject keystrokes, terminal escape sequences or an early submit.

## 13. Updates and dependencies

Use current supported Electron versions.

Keep dependency count small.

Pin lockfile.

Treat packages with native code such as node-pty as security-sensitive dependencies.

### Packaged app hardening

- Electron fuses disable running the packaged app as plain Node (`RunAsNode`), `NODE_OPTIONS` and the `--inspect` debugging entry points.
- macOS builds use the hardened runtime and are signed with Avva Mobile's Developer ID and notarized (on the release Mac, or in CI when the signing secrets are present; docs/RELEASING.md).
- Windows builds are currently unsigned. Updates are trusted because they come only from this repository's GitHub Releases, built by the public release workflow from tagged source (D036).

## 14. Logging

Application logs must not contain:

- passwords
- cookies
- authorization headers
- API keys
- full environment dumps
- unbounded source code

Logs may contain:

- task id
- workspace id
- process state
- safe error code
- timing
- bounded diagnostics

## 15. Destructive actions

Sidekick itself does not perform destructive Git or filesystem operations as part of evidence collection.

Claude may change project files according to its granted permissions, but Sidekick must never convert a review/evidence step into an implicit reset, clean, merge, push or deploy.

## 16. Security acceptance checks

A release is blocked if any of the following is true:

- remote ChatGPT content has Node integration
- remote content can invoke privileged IPC
- microphone permission is globally granted
- Claude is started with an arbitrary shell command from renderer input, or with permission-skipping flags
- cross-workspace Claude session ids can mix
- automatic handoff can occur without explicit user delegation
- credentials appear in normal application logs
- a delegated prompt can reach Claude without control-character sanitizing

## 17. Reporting

Report vulnerabilities privately as described in [.github/SECURITY.md](../.github/SECURITY.md).
